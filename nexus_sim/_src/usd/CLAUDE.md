The nexus component schemas: a Universal Scene Description (USD) plugin with no compiled code, `plugInfo.json` and `generatedSchema.usda` in this folder, and the reader, `reader.py`, that turns a prim's applied schemas into keyword arguments.

- `import nexus_sim` registers this plugin, and the plugin at the root of each package with an entry in the `nexus.registry` entry-point group. OpenUSD reads plugins once, when its schema registry first builds, so import `nexus` before any code opens a stage.
- A schema names its attributes in the `nexus:` namespace, such as `nexus:accNoise`. The reader passes each as the keyword of the same name in snake case, `acc_noise`, and fails on an authored `nexus:` property that no applied schema defines.
- A component that reads a signal more than one component can write, such as `imu`, declares a connection in its schema, a relationship `nexus:inputs:imu`. `NexusPx4API` declares PX4's four, as Newton's `NewtonMimicAPI` declares `newton:mimicJoint`. The reader keeps it out of the keyword arguments, `read_connections` reads its target, and the builder hands the loop the writer it names.
- A nexus schema sits on a Newton prim only when Newton's parser reads it there. `NexusPropellerAPI` sits on the rotor's rigid body, not on its `NewtonActuator` prim: Newton marks that schema family experimental, and its parser keeps an unknown schema only by skipping it.
- A new component schema takes three edits: a type in `plugInfo.json`, a class in `generatedSchema.usda`, and an entry in the `nexus.registry` group of `pyproject.toml` that names its class by import path. The class includes its role schema as a built-in: `prepend apiSchemas = ["NexusSensorRoleAPI"]`. A peer schema, such as `NexusPx4SitlAPI`, takes the first two only: it defines no `nexus:` attribute, so the reader skips it, and the build's peer mapping, not the registry, names its class. A peer schema states no role.
- `NexusSceneAPI` is the one scene schema. It sits on a scene's `PhysicsScene` and authors where the scene sits on Earth, `nexus:geodeticOrigin`, and the world's values beside it: the magnetic field, the pressure at sea level, and the temperature. Each is a custom attribute of Newton's model at world frequency. `nexus_sim/_src/scene/world.py` declares each on the builder under its USD name, so the importer reads what the scene authors, and the sensors read the model. It states no role and has no `nexus.registry` entry, so a vehicle that applies it fails the build, and the conformance fixture, a vehicle, leaves it out.
- A role schema, `NexusSensorRoleAPI`, `NexusEstimatorRoleAPI`, `NexusControllerRoleAPI` or `NexusForceRoleAPI`, defines no attribute. `ROLES` in `reader.py` maps each to its role. The build reads a component's role from its schema, never from its class's methods, and fails a component schema that states no role or two. Each role has its place check: the sensor's in `nexus_sim/_src/vehicle/sensors/declared.py`, the controller's and the estimator's in `nexus_sim/_src/build/components.py`. The force role has none yet.
- A sensor schema sits on the sensor's mount prim, a geometry prim whose parent is the rigid body it rides. It includes `NewtonSiteAPI` as a built-in, so Newton's importer loads the prim as a site, and defines `nexus:rate` in hertz, the attribute every sensor schema shares. Its class takes the model and the prim's path, the site's label, then the keyword `seed` and the attributes of the schema. It states a peer it requires in a `requires` tuple, whose link the loop hands it at `connect`. `nexus_sim/_src/vehicle/sensors/declared.py` builds it. The RTX sensor schemas sit on `Camera` and `OmniLidar` prims, which are no sites: their classes find their body by the prim's path and read the prim through the Kit link.
- A schema of a component with no geometry, a controller or an estimator, applies to `Scope` alone. Its prim is a `Scope` of its own under the vehicle's root prim, by convention named for its role, such as `/astro_max/Controller`. A peer schema the component declares sits beside it, as `NexusPx4SitlAPI` beside `NexusPx4API`. The build finds each by its schema, not by its path.
- `apiSchemaCanOnlyApplyTo` in `plugInfo.json` names the prim types a schema applies to, and the reader fails a schema on any other type.
- A type's name in `plugInfo.json` differs from its schema identifier, `NexusSchemaImuAPI` for `NexusImuAPI`: registration raises when the two match.
- A released schema changes only by a new version. An attribute can join a version with a fallback, and a connection can join one too. A renamed or removed attribute or connection, or a new type, fallback or unit, is a new version, and `tests/usd/test_versions.py` fails an in-place change against `released.json`.
- After any edit to `generatedSchema.usda`, run `uv run python -m nexus_sim._src.usd.released` to rewrite `released.json`. A test fails when the record isn't what the command writes. Review the record's diff: an added line is a new schema or attribute, and a changed line is an in-place change.
- To add a version, add the class with OpenUSD's suffix, `NexusImuAPI_1`, as a new schema beside the old one, with its own type in `plugInfo.json` and its own `nexus.registry` entry. The schema reference page states what it changed.
- To retire a version, remove its class, its type and its `nexus.registry` entry, and list its identifier under `NexusRetiredSchemas` in the `Info` block of `plugInfo.json`. It stays in `released.json`, and the check fails a version that the plugin neither defines nor lists. The reader then fails an asset that applies it and names the prim, the version, and the nexus version. A retirement lands as a `feat!` commit that names the version, so the changelog lists it.
- Each attribute's doc ends with a `Range:` line and a `Units:` line, which `docs/hooks/schemas.py` renders into the schema reference page.
- `tests/usd/conformance.usda` applies every component and peer schema the plugin defines, and a test fails when it misses one. The test leaves out the role schemas, which a component schema includes as a built-in: extend `tests/usd/author_conformance.py` and run it to rewrite the fixture.
