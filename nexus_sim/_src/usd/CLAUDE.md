The nexus component schemas: a Universal Scene Description (USD) plugin with no compiled code, `plugInfo.json` and `generatedSchema.usda` in this folder, and the reader, `reader.py`, that turns a prim's applied schemas into keyword arguments.

- `import nexus_sim` registers this plugin, and the plugin at the root of each package with an entry in the `nexus.components` entry-point group. OpenUSD reads plugins once, when its schema registry first builds, so import `nexus` before any code opens a stage.
- A schema names its attributes in the `nexus:` namespace, such as `nexus:accNoise`. The reader passes each as the keyword of the same name in snake case, `acc_noise`, and fails on an authored `nexus:` attribute that no applied schema defines.
- A nexus schema sits on a Newton prim only when Newton's parser reads it there. `NexusPropellerAPI` sits on the rotor's rigid body, not on its `NewtonActuator` prim: Newton marks that schema family experimental, and its parser keeps an unknown schema only by skipping it.
- A new component schema takes three edits: a type in `plugInfo.json`, a class in `generatedSchema.usda`, and an entry in the `nexus.components` group of `pyproject.toml` that names its class by import path. A peer schema, such as `NexusPx4SitlAPI`, takes the first two only: it defines no `nexus:` attribute, so the reader skips it, and the build's peer mapping, not the registry, names its class.
- A sensor schema sits on the sensor's mount prim, whose parent is the rigid body it rides, and defines `nexus:rate` in hertz, the attribute every sensor schema shares. Its class takes the run's values, a `SensorRun` from `nexus_sim/_src/core/interfaces.py`, as its first argument, and states a peer it requires in a `requires` tuple: `nexus_sim/_src/vehicle/sensors/declared.py` builds it.
- `apiSchemaCanOnlyApplyTo` in `plugInfo.json` names the prim types a schema applies to, and the reader fails a schema on any other type.
- A type's name in `plugInfo.json` differs from its schema identifier, `NexusSchemaImuAPI` for `NexusImuAPI`: registration raises when the two match.
- A released schema changes only by a new version. An attribute can join a version with a fallback. A renamed or removed attribute, or a new type, fallback or unit, is a new version, and `tests/usd/test_versions.py` fails an in-place change against `released.json`.
- After any edit to `generatedSchema.usda`, run `uv run python -m nexus_sim._src.usd.released` to rewrite `released.json`. A test fails when the record isn't what the command writes. Review the record's diff: an added line is a new schema or attribute, and a changed line is an in-place change.
- To add a version, add the class with OpenUSD's suffix, `NexusImuAPI_1`, as a new schema beside the old one, with its own type in `plugInfo.json` and its own `nexus.components` entry. The schema reference page states what it changed.
- To retire a version, remove its class, its type and its `nexus.components` entry, and list its identifier under `NexusRetiredSchemas` in the `Info` block of `plugInfo.json`. It stays in `released.json`, and the check fails a version that the plugin neither defines nor lists. The reader then fails an asset that applies it and names the prim, the version, and the nexus version. A retirement lands as a `feat!` commit that names the version, so the changelog lists it.
- Each attribute's doc ends with a `Range:` line and a `Units:` line, which `docs/hooks/schemas.py` renders into the schema reference page.
- `tests/usd/conformance.usda` applies every schema the plugin defines, and a test fails when it misses one: extend `tests/usd/author_conformance.py` and run it to rewrite the fixture.
